Article 32 data, software, and interpretation notice
===================================================

Biological source
-----------------
All three read types come from the same uneven synthetic MOCK1 DNA sample:
71 microbial strains, ENA sample SAMEA14435832, project PRJEB52977. The source
study is Meslier V, Quinquis B, Da Silva K, et al. Benchmarking second and
third-generation sequencing platforms for microbial metagenomics. Scientific
Data. 2022;9:694. DOI: 10.1038/s41597-022-01762-z (CC BY 4.0).

The Illumina HiSeq 3000 run is ERR9765746, the historical ONT MinION R9 run is
ERR9765780, and the PacBio CCS/HiFi run is ERR9765783. These are real reads
from the same DNA, not simulated reads. That controls biological composition,
but it does not equalize read yield, read length, chemistry, library process,
or error model. The workflow is therefore an assembly-strategy audit rather
than a causal sequencing-platform trial.

Reference and publication anchors
---------------------------------
The official author repository is locked at commit
a429a3724d4593f35b8d7323b20252a6be90e1cd. Supplementary Table S1 defines
mock membership, expected abundances, and accession mapping. Supplementary
Table S2 provides the published short-only, Illumina+ONT, ONT-only,

Prespecified assembly and polishing branches
---------------------------------------------
Three SPAdes 4.3.0 branches use the same fastp-filtered ten-million Illumina
pairs and k=21,33,55,77: short-only; supplementary historical ONT R9 reads;
and supplementary PacBio HiFi reads. SPAdes is a short-read-first graph in
both hybrid branches; --nanopore and --pacbio do not convert it into a
long-read-first assembler.

The long-read-first ONT draft and HiFi comparator read checksum-locked frozen
Flye 2.9.6 outputs generated from the complete ERR9765780 and ERR9765783
archives. The chapter records the exact reconstruction commands; no output
from another chapter's work directory is required. The ONT draft is polished
once with Polypolish 0.6.1 after BWA-MEM 0.7.19 maps mates separately with -a
and Polypolish filters paired alignments. Default and --careful branches are
both retained. Polypolish targets bacterial isolate assemblies; on a
strain-rich metagenome, cross-mapping in conserved regions can introduce as
well as fix consensus changes. Polishing is therefore judged against the 71
known truth references, not accepted from a change count alone. Polypolish
0.6.1 preserves the first-field contig identifier and appends `polypolish` in
the FASTA description field. The sequence audit requires that exact header
annotation plus a one-to-one identifier set and order before comparing
per-contig sequence hashes and length deltas.

All seven assemblies are normalized at >=1,000 bp and evaluated by MetaQUAST
5.3.0 with its bundled minimap2 2.28-r1209, minimum alignment 500 bp, and
identity >=97%. The standalone minimap2 2.31 package is not the aligner used
for these MetaQUAST tables. Per-genome recovery is reported for all 71
references; >=99% genome fraction is an operational
full-genome threshold, not proof of an error-free closed genome. The original
study's --split-scaffolds setting is retained, but any *_broken output is kept
in a separate sensitivity ledger and is never counted as an eighth primary
assembly. Missing reference-by-branch report columns are represented as
explicit zero-recovery rows rather than silently dropped. Mismatch and indel
rates for those rows remain NA because no aligned denominator exists.

Interpretation boundary
-----------------------
N50, genome fraction, complete-genome count, mismatch/indel rate,
misassemblies, unaligned sequence, runtime, and peak memory answer different
questions. A hybrid branch is not an unconditional upgrade when contiguity or
recovery rises while consensus error, strain collapse, or resource cost also
rises. Modern high-accuracy long reads can make short-read polishing
unnecessary; the decision must be supported by the project's own truth,
read-backed variants, coding-sequence integrity, or orthogonal controls.

Raw reads and third-party references are not presented as repository-authored
content. Repository text, new scripts, normalized summaries, and original
redraws follow the repository licenses; third-party attribution and license
boundaries remain explicit.
